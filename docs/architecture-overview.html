Agent Sandbox Platform

architecture overview · generated from docs/DESIGN.md, docs/INVARIANTS.md, ADR-001…008, deploy/k8s/README.md

A microVM sandbox platform for AI agents. Each agent's workload runs inside a Firecracker microVM (stronger isolation than a Kubernetes namespace, INV-027), behind a durable control plane that treats the sandbox as a logical entity — workspace generations and execution epochs survive the compute they ran on. Sandboxes suspend and resume: full-VM checkpoints form incremental chains (ADR-006), and a suspended sandbox springs back to life when traffic arrives at its endpoint (ADR-007/008). A fail-closed egress policy decides which networks a guest may reach, and endpoint bindings expose selected guest ports to clients — with traffic-triggered resume making suspended sandboxes transparently addressable.

    03Trust & security model

    The platform assumes guest code is untrusted (it is AI-generated) and host components can be stale, partitioned, or replayed. Every boundary below fails closed.

    Isolation classes (ADR-001, ADR-004)

    One production isolation class: Firecracker microVMs — a jailed VMM process per sandbox, KVM-enforced boundary, stronger than Kubernetes namespace isolation (INV-027). The fake, local (process), and isolated (bwrap) backends exist only as contract-verified test doubles: the same conformance scenarios run against every backend with differences expressed as declared capabilities (INV-026). A single Go module, no containerd/Redis dependency surface.

    Fail-closed egress (network/network.go, backend egress chains)

    Default-deny: a guest reaches only what its network.EgressPolicy allows; anything unclassifiable is denied. Each incarnation gets per-TAP iptables chains named FC-EGR-<slot>-g<N> — the generation N is stamped into the datapath, so a policy change or a snapshot rollback bumps the generation, swaps chains atomically (build FC-TMP-* → verify with -C → retarget jumps), and flushes guest conntrack so established flows die with the old policy. A per-incarnation DNS-learning proxy on the TAP host address answers only allowed names and installs the returned IPs as /32 allows with TTL reaping. The cloud metadata address (169.254.169.254) is always blocked; IPv6 is fail-closed by design.

    Port publishing (runtime/firecracker-backend/publish.go)

    Endpoint bindings DNAT a host port into the guest (FC-PUB-* chains). Three rules keep this safe: (1) both hooks (PREROUTING, OUTPUT) match -m addrtype --dst-type LOCAL — only traffic destined to the host's own addresses is redirected; forwarded and host-outbound traffic on the same port is never hijacked. (2) a floor of 1024 plus a configurable deny-list (default 6443, 8080, 10250 — API server, control plane/proxy, kubelet) is enforced in the backend with a typed ErrPortConflict. (3) publish/unpublish RPCs are fence-validated: a stale control-plane view gets ErrStaleFence, not a DNAT rule.

    Fencing & epochs (ADR-002)

    Two monotonic counters do the safety work. Execution epochs: volatile execution state has an epoch (INV-007); a continuity-preserving resume keeps it, a workspace-only recovery bumps it, and endpoint bindings are fenced to the epoch they were created in — stale-epoch bindings deny at the gateway. Placement fences: the scheduler issues a per-sandbox fence on every placement; host agents reject creates/restores/publishes carrying an older fence, which is how the system guarantees never two live incarnations of one sandbox even across retries, lost ACKs, and host restarts.

    06Proof status — what is actually verified

    An honest account. "Green" means go test ./... -count=1 with zero FAILs.

    Proven

    • Unit/conformance suite — ~10 Go packages covering the in-memory, fake, and local (bwrap) backends plus a chaos harness (host loss, re-registration, interrupted operations). All green locally.
    • Real-microVM proof — FC_TEST=1 suites on an aarch64 KVM bare-metal host: conformance ~230s + firecracker-backend ~378s, green. Covers incremental snapshot chains, corruption detection, egress generations, port publish (dst-type-LOCAL scoping), and routed restore.
    • Deployed proof — a k3s cluster on the bare-metal host ran live smoke tests: create → bind → curl via DNAT → guest response; suspend (RAM reclaimed) → hostname request → single-flight routed restore → 200 with the epoch preserved and a tmpfs marker alive; denied ports refused.
    • Deterministic simulation (SandboxLab, ADR-010) — the real control plane (manager, fleet, scheduler) driven in-process by a virtual clock and seeded event queue; same seed ⇒ byte-identical trace (a gate test). Scenario suites prove: a 200-sandbox cold-start storm respects capacity exactly (arrivals beyond fleet capacity fail honestly), a 100-sandbox resume burst routes exactly one restore RPC per incarnation (single-flight) with continuity preserved, origin-host loss mid-restore falls back honestly (workspace-only, epoch bump, ExecutionStateReset), a kernel-mismatched fleet claims no checkpoint-locality bonus, and suspend/resume churn under capacity pressure leaks nothing. Scale smoke: 10k logical / 200 live sandboxes in ~4s wall. Every scenario runs under the executable invariant engine (phase 3): 20 of the 30 architectural invariants are continuously checked from the event stream + state snapshots (2 more scenario-asserted, 8 documented not-sim-checkable), violations are typed trace events that fail the test, and planted-violation meta-tests (double-registered incarnation, dropped reset event, oversubscribed host) prove the checkers fire. Phase 4 adds declarative JSON scenarios (sandboxlab/scenarios/: cold-start-storm, resume-storm, host-loss-mid-restore, guard-mismatch, checkpoint-gc-churn, traffic-resume-race) and the sandbox-lab CI runner (run/run-all/list, exit 0/1, verdict block, deterministic trace artifact). Phase 5 adds an enriched JSONL trace (causal parent links, inline world snapshots, embedded invariant report) and a self-contained time-travel replay UI (sandbox-lab render/replay): scrub virtual time, inspect hosts/sandboxes/ events with causal-parent jumps, and click violations to jump to the offending seq.
    • Two-machine fleet proof — standalone control-planed on node 1 plus one host-agentd per node (two AWS aarch64 instances, kernels 6.8 and 7.0): both hosts register with distinct facts and capacity; endpoint DNAT serves a guest HTTP server cross-machine (curl from the peer node → 200); suspend → resume on the origin host preserves RAM state and epoch; real host loss (killed host-agentd) is latched down in ~6 s, declared lost, and the sandbox goes FAILED, then re-materializes on the surviving host with an epoch bump, ExecutionStateReset, and the committed workspace intact. The run also exposed and fixed two control-plane robustness bugs (an unbounded heartbeat RPC wedging the fleet lock, and a miss-counter reset stalling lost-host declaration). FC conformance suites are green on the second node too.

    Not yet proven

    • Cross-machine checkpoint restore with RAM continuity — correctly refused when host kernels differ (node 1: 6.8, node 2: 7.0): the scheduler's facts guard finds no candidate, and even with advertised facts overridden (HOST_FACTS_OVERRIDE test seam) the backend's snapshot-package validation vetoes on the real uname — workspace-only fallback preserves the committed workspace either way. The ADR-009 pull path itself engaged (checkpoint package transferred to the peer) before the veto; a full RAM-continuity pull across machines needs matching kernels and remains proven only in the two-agent single-node topology. Joining node 2 into the k3s cluster is also deferred (kernel 7.0 kubelet/cadvisor risk; the standalone topology was chosen instead).
    • Scale/load — logic-level scale is covered by SandboxLab (ADR-010: storms, bursts, 10k logical sandboxes, byte-identical traces), but real-time density and contention on actual hosts is untested; virtual latency models work, not contention. One load-sensitive FC test flake observed (egress-chain cleanup assertion failing only while the host also ran 16 fleet VMs; green idle).
    • Production hardening — dev shared-token auth everywhere; the endpoint proxy dials heartbeat-self-reported host URLs (L11 SSRF posture, accepted for dev).
    • Portability — arm64 (aarch64) only so far.
    • Long-run stability — no soak testing; one unreproduced flake observed.
    • HA control plane — control-planed is a single Deployment with a file store, not a real highly-available control plane.

    07Known gaps & roadmap

    • Origin-destroyed checkpoint recovery — cross-host restore (ADR-009) ships: the destination host pulls the snapshot package from the origin over the host-agent RPC (per-file sha256 against capture-time hashes, staged atomic install, GC pinning). It needs the origin alive to serve the package; a shared snapshot store for the origin-destroyed case is the documented next step.
    • CubeSandbox borrow list, remaining — the P2 grab-bag (guest-ready MMIO signal, TAP pool pre-warming, flattened workspace-generation chains, per-sandbox traffic tokens, audit fingerprints) and P1.8 (HSet-snapshot + capped-stream push pattern to a gateway tier). All P0/P1 items except P1.8 are DONE — see docs/COMPARISON-CUBESANDBOX.md.
    • Jailer upstream PR — deferred; the backend currently carries its own jail setup.
    • Accepted lows from the 2026-09-16 code review (Batches A–C fixed the rest): L9 netinit sysctl is node-wide and persists after the pod (documented, dedicated nodes assumed); L11 the endpoint proxy trusts heartbeat-self-reported host URLs (dev shared-token posture); L12 stale name→binding cache for up to CacheTTL after unbind/recreate; caches unbounded; L14 jail pre-spawn bind mount is rw without nodev/nosuid (largely inherent).
    • Tools-image GC — done (content-addressed reference counting with chain coverage); the tools image also travels with the snapshot package on cross-host restore (ADR-009), and the destination's meta.json is rewritten to its local path at install time.
