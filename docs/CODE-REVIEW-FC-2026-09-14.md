# Code Review — Firecracker backend & related changes — 2026-09-14 (PM)

**Scope:** all changes since docs/CODE-REVIEW-2026-09-14.md — the review-fix commits plus the entire Firecracker backend (`runtime/firecracker-backend/`, `runtime/guest-supervisor/cmd/guest-supervisor/`, wire protocol, manager CheckpointReclaimsMemory changes, conformance wiring, ADR-001).
**Method:** three parallel deep reviewers; verified against ADR-001 and INVARIANTS.
**Status legend:** [ ] open, [x] fixed (reference fixing commit)

## High severity

- [x] **FH1 — `runtime/firecracker-backend/image.go:73-95` + `agent_linux.go:353` — debugfs script injection via workspace filenames.** Manifest paths are interpolated raw into a debugfs command script; `checkWorkspacePath` blocks `..`/absolute but not newlines/whitespace. A guest (root in VM) creates a file named with `\n` via supervisor `WriteFile`; the name round-trips through `WorkspaceFiles` → workspace commit → next materialize, and the injected debugfs command runs as the host backend user (`write`/`dump` = host file read/write). Agent-reachable host injection, same class as H7 in the previous review. Fix at both layers: reject newline/whitespace/metachars in workspace paths. **Fixed:** shared `supervisor.CheckWorkspacePath` (control/whitespace/backslash rejected — debugfs tokenization verified empirically on debugfs 1.47) enforced by the guest agent and the host image builder independently; regression tests `TestCheckWorkspacePathStrict`, `TestBuildWorkspaceImageRejectsMetachars`, `TestWorkspaceInjectionRoundTrip`.

## Medium severity

- [x] **FM1 — `net.go:245` — no cross-VM/anti-spoofing isolation.** Egress chain matches only `-i <tap>` + destination; with DefaultAllow, guest A reaches guest B's /30 IP and host tap IPs directly (cross-tenant VM-to-VM). No `-s <guestIP>` source filter → guest (root) can spoof source IPs. Need a rule dropping tap-ingress to 192.168.0.0/16 (except own host IP) + source filter. **Fixed:** anti-spoof `! -s <guestIP> DROP` precedes the chain jump in both FORWARD and INPUT (chain jump also carries `-s`); the chain drops `169.254.0.0/16` (link-local) and the whole VM subnet `192.168.0.0/16` (cross-VM + host tap side) right after the metadata DROP. DNS: guest resolv.conf was empty (no host-resolver dependency existed); the guest unit now points it at a public resolver — DNS is ordinary egress under the same policy. Regression tests `TestCrossVMIsolationAndSpoofing` (cross-VM + tap-side unreachable, spoof counter increments) and updated `TestEgressPolicy` (targets the host uplink IP; DNS resolution verified).
- [x] **FM2 — `net.go` — IPv4-only enforcement.** No ip6tables chain; guest root can bring up IPv6 (link-local/ULA) and reach host services or IPv6 metadata endpoints (`fd00:ec2::254`) bypassing all policy. Disable IPv6 in-guest or mirror chains in ip6tables. **Fixed (both layers):** the guest network unit sets `net.ipv6.conf.all/eth0.disable_ipv6=1`, AND a per-incarnation ip6tables chain (`FC-EGR6-<slot>`, DROP all) is hooked into FORWARD+INPUT for the TAP — host-enforced even if the guest re-enables IPv6; host IPv6 forwarding is never enabled. Regression test `TestIPv6Blocked` (no inet6 on eth0, IPv6 egress fails, DROP chain hooked).
- [x] **FM3 — `net.go:41-63,198` — hash-derived TAP/IP/chain names collide.** FNV32 % 8192 /30s: ~50% collision at ~110 live incarnations. On collision `setupNetworking` deletes the *other* VM's TAP ("delete leftover first"), breaking a running VM. Detect live collision and error, or use a unique counter. **Fixed:** process-local slot allocator (`slotAlloc`, one /30 per slot, TAP/chain/IP/MAC derived from the slot number) with hash-preferred slot + linear-scan collision resolution; a slot whose TAP exists but is not registered to the requesting incarnation is skipped, never deleted; slots are allocated at Create (guest unit matches the TAP), released at teardown, and recorded in snapshot metadata (`net_slot`) so restore reuses the same slot. Regression test `TestNetworkSlotCollision` (space shrunk to 2: colliding incarnation gets a distinct slot, first VM's TAP/chain untouched, exhaustion errors cleanly, teardown releases).
- [x] **FM4 — `net.go:146-179` — hostname policy resolved once at setup.** DNS rebinding TOCTOU between LookupIP and rule install; stale allow/deny entries. Document or re-resolve periodically. **Fixed (both mitigation and documentation):** a per-incarnation re-resolver goroutine (`reResolveLoop`, started only when the policy contains hostname entries) re-resolves every `Config.ReResolveInterval` (default 60s) and atomically swaps the chain — build a fully-populated `<chain>.tmp`, retarget the FORWARD/INPUT jumps by rule position (`-R`), flush+delete the old chain, rename tmp into place; any failure keeps the old rules. ADR-001 documents the residual limitation: enforcement tracks the LAST resolved addresses between ticks, and security-sensitive denies should use IP/CIDR entries. Regression test `TestHostnamePolicyReResolve` (1s interval, deny `localhost`: rules intact after multiple swaps, no tmp-chain leak, FORWARD jump intact).
- [x] **FM5 — `backend.go:895` vs `561` — `Exec` races `Snapshot` pause.** Both check `inc.paused` under lock but act after unlock; an Exec in flight during pause fails with a confusing timeout while the wsMirror update still lands (dirty-tracking skew, INV-006). Per-incarnation op lock or re-check around the vsock call. **Fixed:** per-incarnation `opMu` serializes guest-mutating ops against the pause/capture window. `Exec` acquires `inc.opMu` and re-checks `started && !paused && !dead` before any vsock call, so a racing Exec either fully lands in the guest before the pause or fails with `ErrIllegalState` — the wsMirror is only updated after guest-confirmed writes. `Snapshot` holds `opMu` across pause + drive copy + snapshotCreate; `WaitExecution` deliberately does not take `opMu` (a blocking Wait may span a snapshot). Regression test `TestExecSnapshotRace` (4 goroutines spamming write-execs during Snapshot: every error is `ErrIllegalState`, every successful write visible in guest AND mirror, no failed write in the mirror).
- [x] **FM6 — `backend.go:658` + `jail.go` — jailed `Restore` leaks old jail + `/snap` bind mount.** `Restore` resets jailRoot without unmounting; `prepareJail`'s RemoveAll fails on the mountpoint (error ignored); repeated jailed restores stack mounts. Jailed restore is also never exercised by tests. **Fixed:** `Restore` now runs `stopProc` + `cleanupJail` (unmount `/snap`, remove jail tree) on any pre-existing incarnation BEFORE re-jailing; `prepareJail` proactively unmounts a stale `/snap` bind and its RemoveAll failure is fatal, never ignored. `bindMount` is idempotent (reuses an existing mount instead of stacking), and `unmountRetry` retries the umount for ~1s because the jailer's shared-namespace peer mount teardown lags process death (an immediate `umount -l` can fail EINVAL; verified empirically on the KVM host). Regression test `TestJailedRestoreCleansStaleJail` (jailed boot → snapshot → crash-style `stopProc` with jail intact → restore → exec works, twice; `/proc/self/mountinfo` shows exactly one snap mount at every stage, never two).
- [x] **FM7 — `backend.go:148,210,280` + snapshot dirs — world-readable guest memory/workspace under /tmp.** Root/incarnation dirs 0755, console.log/drives 0644, snapshot dirs (full guest RAM) 0755. Any local user reads guest memory + tenant data. Should be 0700. **Fixed:** backend Root + snapshots dir + incarnation dirs + jail tree + snapshot dirs are 0700 (explicit `os.Chmod` after creation, umask-independent); console.log, rootfs/workspace drives, mem.file/vm.state, and meta.json are 0600 (the VMM-written snapshot files are chmod'd after snapshotCreate, covering the root-jailer case). Regression test `TestArtifactPermissions` (stats every artifact path and asserts exact permission bits after Create+Start+Snapshot).
- [x] **FM8 — `backend.go:209` + `jail.go:186` — `IncarnationID` never validated.** `..` escapes Root; `cleanupJail` falls back to `sudo rm -rf <base>/firecracker/<id>` — root-deletion primitive if an unsanitized ID ever arrives. Also interpolated into systemd unit (image.go:169). Whitelist `[A-Za-z0-9._-]`. **Fixed:** `validateIncarnationID` (`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$` + explicit `..` rejection) at the Create/Restore boundary before any filesystem, jailer, systemd, or sudo use; regression test `TestIncarnationIDValidation` (bad IDs error, no dirs created, Restore gated too).
- [x] **FM9 — `manager.go:1415-1422` — reclaim-class checkpoint suspend doesn't free quota.** Handle stays in `m.handles`, so quota still counts the (terminated, RAM-reclaimed) sandbox as live; `preemptableLocked` can also pick the already-suspended sandbox and the preemption loop breaks on the illegal transition, failing a placement another victim could satisfy. Needs a conformance test pinning intended semantics. **Fixed:** the reclaim-class branch of `checkpointSuspendLocked` now drops the handle with the terminated VM, so quota accounting and victim selection (both keyed on `m.handles`) skip the suspended sandbox naturally — same treatment workspace-only suspends already had. `Resume` attempts `rt.Restore` whenever a checkpoint exists and (`handle live` OR `CheckpointReclaimsMemory`), re-registering the handle Restore returns; restore failure with a live handle still cleans up and falls back to workspace-only recovery. The preemption loop now excludes a victim whose suspend fails and tries the next-lowest-priority victim instead of breaking (or retrying the same victim 8x). Conformance test `TestFirecrackerCheckpointSuspendReclaimsQuota` (MaxLiveSandboxes=1: checkpoint-suspend frees the slot, second materialize succeeds with no QuotaExceeded event, continuity resume intact).
- [x] **FM10 — `vsock.go:101` + `manager.go:1051` — blocking `Wait` has no deadline and runs under the manager mutex.** A wedged guest supervisor with a live VMM hangs WaitExecution forever → entire control plane wedged. Generous-but-finite timeout or cancel path. **Fixed (both layers).** (a) `Manager.CompleteExecution` no longer holds `m.mu` across `rt.WaitExecution`: it validates under the lock, waits unlocked, then re-locks and re-validates — an execution already finalized concurrently (reconciler/duplicate call) returns its recorded state without re-appending the outcome or re-committing. (b) `vsockSupervisor.Wait` runs a liveness watchdog instead of an absolute timeout (long commands are legitimate): every 5s it checks VMM process liveness (wired from `inc.exited` via a new `alive` hook) and probes `Health` on a second connection; a dead VMM or 3 consecutive probe failures abort the wait with the new typed `supervisor.ErrUnhealthy`. A SIGKILLed agent also fails fast (connection EOF). Regression test `TestWedgedSupervisorWaitReturns` (SIGSTOP the guest agent mid-`sleep 300`: wait aborts with `ErrUnhealthy` in ~40s, VMM stays alive, Terminate still works); control-plane responsiveness under a wedged guest is covered by the full conformance suite against the restructured `CompleteExecution`.
- [x] **FM11 — `backend.go:256` — no crash recovery for host plumbing.** Backend process death leaks TAPs, FC-EGR chains, MASQUERADE, jail mounts/cgroups; `New()` does no sweep of `fc-tap-*`/`FC-EGR-*`. Startup sweep needed. **Fixed:** `New()` sweeps before serving: `sweepStaleNetworking` collects slot numbers from `ip -o link` (`fc-tap-N`) and `iptables/ip6tables -S` (`-N FC-EGR-N` / `FC-EGR6-N`) — only exact platform prefixes with valid slot indices — skips any slot still registered to a live incarnation of this process, and reclaims the rest through the same `cleanupNetDevices` path; `sweepStaleJails` (when the jailer is configured) unmounts any `/snap` bind under the chroot base found in `/proc/mounts` and removes jail trees whose names pass `validateIncarnationID`. Errors are logged loudly to stderr, never fatal. Regression test `TestCrashRecoverySweep` (networked incarnation, VMM killed crash-style with plumbing intact, slot registration cleared; second `New()` removes the TAP and both chains — sweep log line observed).
- [x] **FM12 — `agent_linux.go:111-115` — data race on trackedExec fields** (pgid/startedAt/result written after publish, read without sync by Status/baselinePGIDs). Inherited parity defect from local supervisor; standalone daemon blast radius differs. **Fixed:** `startedAt`/`pgid`/result refs are written under `a.mu` immediately after `cmd.Start` and before the wait goroutine begins; the wait goroutine now writes the completion result under `a.mu` and closes `done` AFTER the writes (the channel close is the happens-before edge for `Wait` readers); `Status` reads all fields under `a.mu`; `baselinePGIDs` already held the lock and is now safe by construction. Unit tests in `runtime/guest-supervisor/cmd/guest-supervisor/agent_test.go`, including `TestExecFieldsPublishedBeforeReturn` (concurrent Status/baselinePGIDs readers); the package passes `go test -race` on linux/arm64.
- [x] **FM13 — `protocol.go:47,70` + `agent_linux.go:381` — binary workspace files corrupted on the wire.** Files/Content are Go strings through encoding/json → invalid UTF-8 silently replaced with U+FFFD both directions. base64 the values or enforce text-only contract. **Fixed:** `Request.Content` and `Response.Files` values are now `[]byte` (automatic base64 through encoding/json); guest agent and host vsock transport convert at the boundary (lossless). Host manifest/wsMirror stay strings — verified the only content-carrying JSON boundary was the supervisor wire (the durable workspace store persists raw blob files + digest manifests, no content JSON). Regression test `TestBinaryWorkspaceRoundTrip` (all 256 byte values + invalid UTF-8: write → WorkspaceFiles → rematerialize → guest fs size, all byte-identical).

## Low severity

- [x] **FL1 — `agent_linux.go:353-378` — workspace path check is lexical only; symlinks escape.** A symlink in /workspace redirects WriteFile/ReadFile outside the root; `WorkspaceFiles` ships `/etc/shadow`-class content to the host manifest. O_NOFOLLOW / skip non-regular files. **Fixed:** `WriteFile`/`ReadFile` open the final component with `O_NOFOLLOW` (ELOOP on a planted symlink); the `WorkspaceFiles` walk ships only regular files (Walk uses Lstat, so symlinks/devices/FIFOs are skipped, never followed). Regression test `TestWorkspaceSymlinkEscape` (symlink → /etc/passwd: ReadFile and WriteFile error, manifest excludes it; regular files unaffected).
- [x] **FL2 — `agent_linux.go:175` — `Cancel` group-kills without PID/PGID-reuse recheck** (TerminateBackground has markerOwned; Cancel doesn't). Same for per-PID kill after group kill in TerminateBackground. **Fixed:** `Cancel` reads the recorded pgid under lock and skips the group-kill only when the group leader is POSITIVELY disowned (new `markerDisowned`: readable non-empty environ lacking the marker) — an unreadable/empty environ (zombie, or the brief post-exec procfs window, observed in testing) is inconclusive and falls back to killing, preserving prior semantics. `TerminateBackground` now also rechecks the group leader (`p.PGID == p.PID || markerOwned`) before signaling the whole group; the per-PID recheck it already had is unchanged. Regression test `TestCancelRechecksOwnership` (foreign pgid untouched — verified the test process survives; real exec's whole group killed).
- [x] **FL3 — `agent_linux.go:103` — failed `cmd.Start` leaks waiters** (exec entry deleted but `t.done` never closed → Wait blocks forever). Parity defect with local. **Fixed:** on Start failure the entry is kept with a recorded error result (`ExitCode: -1`, `CompletedAt` set) and `done` is closed, so Wait/Status return promptly and the failure is observable. Regression test `TestFailedStartClosesDone` (Exec with a missing workdir errors; Wait returns the -1 result within a 5s bound).
- [x] **FL4 — `agent_linux.go:205` — premature EOF with background writers** (EOF when main shell exits but descendants still append to spill files). Parity; doc note at minimum. **Fixed (comment only, per scope):** `ReadOutput`'s doc now defines EOF precisely — "main command exited and read reached current end of file" — and states that trailing background output requires polling again after completion.
- [x] **FL5 — `vsock_linux.go:38` + `main.go:52` — no idle timeout on accepted vsock connections**; stalled peer leaks goroutine+fd and busy-polls vCPU; EMFILE → permanent hot error-spin. **Fixed:** accepted connections carry a 30s first-frame idle deadline (`vsockConn.deadline`, enforced in the nonblocking read poll, cleared once the first frame arrives so long Waits may idle); the accept loop backs off 200ms on EMFILE/ENFILE instead of hot-spinning.
- [x] **FL6 — `backend.go:658-670` — failed `Snapshot` leaves VM paused + partial dir** counted toward GC (wedge class). Also stale-checkpoint ambiguity on Terminate failure in checkpointSuspendLocked (manager.go:1415). **Fixed (backend half):** every post-pause failure path in `Snapshot` routes through a `fail` helper that best-effort resumes the VM when Snapshot paused it and removes the partial snapshot dir (never counted toward GC, never mistaken for a restorable checkpoint). The manager-side ambiguity is already handled: `checkpointSuspendLocked` resumes the VM on Snapshot error and `suspendWithReasonLocked` falls back to workspace-only suspend; a Terminate failure after a successful snapshot leaves both the checkpoint record AND the live handle intact, so the sandbox is resumable — no divergence. Regression test `TestSnapshotFailureResumesAndCleans` (injected snapshotCreate fault: Snapshot errors, VM unpaused and Alive, zero snapshot dirs, exec works, retry without the fault succeeds).
- [x] **FL7 — `backend.go:734` + `net.go:256` — blocking sudo/kill work under backend-wide lock** (5s VMM-exit wait, 4 sudo calls) stalls all incarnations. **Fixed:** new `stopProc` swaps the process fields under `b.mu` but does the kill + up-to-5s exit wait AFTER unlock (idempotent via nil-ing); `Terminate`/`KillRuntime`/`Close` mark dead under the lock, then stop processes, tear down networking (`cleanupNetDevices` sudo calls), and clean jails outside it.
- [x] **FL8 — `backend.go:84` — `netOnce` caches transient failure forever; MASQUERADE covers all of 192.168.0.0/16** (may NAT unrelated host networks). **Fixed:** the global-net guard is now mutex + success-flag (success cached, FAILURE retried on the next incarnation — transient sysctl/iptables failures no longer disable networking for the process lifetime); the MASQUERADE source is narrowed to `masqueradeCIDR()`, the smallest CIDR covering the configured slot space (/16 at the default 8192 slots; tight /28 in the 2-slot collision test).
- [x] **FL9 — `backend.go:906,102` — per-incarnation maps grow unboundedly** (ops, wsMirror per file version). **Fixed:** completed waits move the result into a bounded cache (`maxCachedResults = 256`, FIFO) and the live `inc.ops` entry is pruned, so repeat Waits stay idempotent while the ops map tracks only not-yet-observed executions. wsMirror verified already latest-version-per-file (single map entry per path) — no growth per version, noted and skipped.
- [x] **FL10 — `conformance/firecracker_test.go:87` — guest build hardcodes GOARCH=arm64** → opaque 120s timeout on x86_64 hosts. Use runtime.GOARCH. **Fixed:** both test helpers (conformance and backend suite) build with `runtime.GOARCH` of the test host, overridable via `FC_GUEST_GOARCH`.
- [x] **FL11 — `manager.go:565` — `materializeLocked` returns on `rt.Start` error without `rt.Terminate`** (lingering incarnation record/net state). Compare startup-failure path two lines below. **Fixed:** `m.rt.Terminate(h)` on Start error, mirroring the startup-failure path (the handle was never registered, so no handle cleanup is needed).
- [x] **FL12 — `net.go:255-267`, `jail.go:173-190` — teardownNetworking locking inconsistency on `inc.net`**; spawnJailed failure after prepareJail leaves jail tree. **Fixed:** all `inc.net` access is now under `b.mu` (`netOf`, `allocateNetworkingLocked` with lock-holding callers, `teardownNetworking`/`cleanupJail` swap fields under the lock and do blocking work after unlock; Snapshot reads the slot under the lock); the spawn path cleans the prepared jail tree via `cleanupJail` when the jailed spawn fails before falling back to a raw spawn.
- [x] **FL13 — `vsock_linux.go:161` — debugDial fd leak** (debug-only). **Fixed:** `defer syscall.Close(fd)` right after socket creation.
